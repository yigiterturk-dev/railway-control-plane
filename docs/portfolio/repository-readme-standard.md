# Portfolio Repository README Standard

Use this structure as a quality contract, not a copy-paste template. Each repository must retain its own voice, domain, screenshots, and architecture.

1. Product name and one precise sentence.
2. Live demo, status, CI, and license signals.
3. Product screenshot showing a real meaningful state.
4. Problem and target user.
5. What the product does, expressed as workflows rather than a feature dump.
6. Engineering highlights with links to code or ADRs.
7. Architecture and request/data flow.
8. Reliability, security, accessibility, and performance decisions.
9. Technology choices and why they fit.
10. Local setup and environment variables.
11. Test and verification commands.
12. Known limitations and roadmap.
13. Personal contribution and project status.

## Evidence rule

Do not publish a number, scale claim, performance result, security claim, or production claim unless it is backed by a reproducible measurement, test, public deployment, or clearly cited data source.
